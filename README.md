# Reserve — Универсална система за резервации

Демонстрационно адаптивно приложение с **React + Vite**, което използва общ модел за резервации и конфигурация за три различни типа бизнес: салон за красота, медицински кабинет и ресторант.

## Стартиране

Необходим е Node.js 18 или по-нова версия.

```bash
npm install
npm run dev
```

Отворете адреса, който Vite показва в терминала (обикновено `http://localhost:5173`).

За production build:

```bash
npm run build
npm run preview
```

## Функционалности

- Превключване между три бизнес конфигурации.
- Списък, търсене и филтриране на резервации.
- Създаване, редактиране, отказ и възстановяване на резервация.
- Избор на ресурс, услуга, дата, продължителност и свободен час.
- Проверка за припокриване на интервали за един и същ ресурс.
- Проверка на капацитет при ресторантски маси.
- Отделен екран за преглед на свободните и заетите слотове.
- Адаптивен интерфейс за настолни и мобилни устройства.

### Универсален модел на данните

Всяка резервация използва обща структура:

- `id` — уникален идентификатор;
- `businessId` — тип бизнес;
- `resourceId` — конкретен ресурс (служител, лекар или маса);
- `customer` — клиент;
- `service` — избрана услуга;
- `date`, `time`, `duration` — времеви интервал;
- `people` — брой гости/участници;
- `status` — `confirmed` или `cancelled`.

Бизнес конфигурацията описва работно време, стъпка на слотовете, стандартна продължителност, услуги, ресурси и етикети за интерфейса. Така общият компонент не съдържа отделна имплементация за всеки бизнес.

## Алгоритми и оптимизация

### Проверка за конфликт

`hasConflict()` сравнява само резервации със същите `businessId`, `resourceId` и `date`. Два интервала се припокриват, когато:

```js
candidateStart < existingEnd && candidateEnd > existingStart
```

Това коректно отчита частично припокриване, включително когато единият интервал започва преди другия. Отказаните резервации не блокират ресурс.

Сложността на проверката в демо реализацията е **O(n)** спрямо броя резервации. При голям обем данни може да се оптимизира чрез индексиране по `(businessId, resourceId, date)` и сортирани интервали/интервално дърво.

### Генериране на слотове

`getAvailableSlots()` генерира начални часове между началото и края на работното време през конфигурирана стъпка. За всеки слот се проверява дали целият интервал с избраната продължителност е свободен.

### React оптимизация

- `useMemo` кешира филтрирания списък, статистиките и изчислените свободни слотове.
- Състоянието е разделено според отговорността: бизнес, резервации, филтри, изглед и модален прозорец.
- Конфигурациите са статични данни извън компонентите.
- Списъците използват стабилни ключове (`id`).

## Симулирани данни и ограничения

Данните се пазят в React state и се инициализират от `initialBookings`. При презареждане промените се губят. Не се използва backend, база данни, автентикация или реално изпращане на известия. В production среда проверката за конфликт трябва да се изпълнява и на сървъра в транзакция, за да се избегнат конкурентни резервации.
